## Findings / surprises
- The post-July degradation is NOT random rate-limit noise: it is a fixed
  crash point at JPM (7th ticker) that truncates every run to the first 5
  tech tickers. A2 already fixes the mechanism; **the fix reaches production
  only when Aaron deploys/restarts the cron on this branch's code.**
- Catch-up alignment note: context-row↔timestamp alignment inherits
  run_once's convention (last X row ↔ last timestamp); SAX word trimming can
  shift by a bar or two vs raw prices — same caveat as the live runner.
- Guard-hook friction: shell commands naming `d1_forward_v1` alongside
  anything write-capable are refused; jq/grep/wc one-liners pass. Census was
  done entirely read-only through those.
